## 一、`last_sync_date` 谎报

`data_hub/router.py` 轮次结尾原来只看早停：

```python
if aborted is None:
    self.db.meta_set('last_sync_date', end)
```

盘中跑批时所有票的当日行都被未定型守卫拦掉，一行未落库，`last_sync_date`
照样前进。现在多一道判定：

```python
wrote_nothing = synced == 0 and skipped_unsettled > 0
advanced = aborted is None and not wrote_nothing
```

关键在于不能只看 `synced == 0`——「全市场已是最新、确实无事可做」也是 0，
那种轮次该推进，两者只能靠 `skipped_unsettled` 区分。判定结果以
`last_sync_advanced` 回到返回值，`__main__` 未推进时打印一行说明，
避免看日志时误以为已同步到 `end`。

四种轮次形态全部覆盖测试（`/tmp/qs_l2_lastsync.py`，5/5 通过）：

| 形态 | synced | skipped_unsettled | aborted | 推进 |
|---|---|---|---|---|
| 盘中全未定型 | 0 | 3 | — | 否 |
| 无事可做 | 0 | 0 | — | 是 |
| 正常写入 | 3 | 0 | — | 是 |
| 早停 | 0 | 0 | 有 | 否 |
| 混合（部分未定型+部分写入） | 1 | 2 | — | 是 |

库内状态已校回：`last_sync_date` 从 `2026-08-31` 改为 `2026-08-28`，
与 `kline` 表 `MAX(date)` 一致。

`--source {baostock,akshare,klinedb}`，覆盖率校验、零值统计、写缓存、

测试 `/tmp/qs_l6_backfill.py`，12/12 通过，含覆盖率不足不写缓存、

## 四、遗留：这三天的结果基于近似成交额

`klinedb` 的 `amount` 是 `均价×volume` 估出来的（腾讯日K 不返回成交额）。
以 08-28 对照新浪精确值实测（5192 只）：

- P1 -2.150% / P50 **-0.157%** / P99 +1.115%，`|误差|>5%` 占 **0.00%**
- 25 亿预筛：精确入池 146 → 一致 143、漏选 3、误入 0

漏选的 3 只全卡在阈值边缘，偏差在 2.3% 以内；**误入 0**，不会把不该进池的
票放进来。所以这三天的结果方向可信，但严格说是下界——理论上各日可能少了
2~3 只边缘票。baostock 或东财恢复后，用
`--source baostock 2026-08-25 2026-08-26 2026-08-27` 重跑缓存再重算，
即可确认差异。

成功调用得出的，站不住——随后连续 5 次重试全是 `RemoteDisconnected`。
