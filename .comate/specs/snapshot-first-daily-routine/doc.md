# 例行任务改为「收盘后快照优先」

## 背景

`run_daily.sh`（launchd 16:15 触发）当前的数据更新步骤是
`python -m data_hub sync_today`，走的是 `sync_kline_db` 的**腾讯逐票**链路。
最近两周的实跑记录显示：09-14、09-18、09-21、09-22、09-23、09-24、09-28、
09-30、10-08 几乎每个交易日的定时同步都因腾讯 WAF 失败或严重不完整，
全靠事后手动补。护栏保证了"不谎报、不拖死"，但"每天手动补"已成常态负担。

与此同时，**新浪快照通道**在这两周被手动用了十几次，每次都是 ~2 秒拿到
全市场精确数据（OHLC + 成交额 + volume），且**不受腾讯 WAF 影响**——
10-09、09-29、09-21 等多日都是靠它秒级补齐的。它天然适合做收盘后的日常驱动：
run_daily 在 16:15 跑，此时快照持有的正是当日收盘定型值。

结论：把例行任务从"腾讯逐票优先"改为"快照优先"。

## 技术方案

### 1. 抽出可复用的快照补数函数

`scripts/fill_kline_from_snapshot.py` 的核心逻辑现在埋在 `main()` 里。
抽成 `fill_from_snapshot(target, dry_run=False) -> dict`，返回
`{wrote, rows, coverage, bad_date, halted, aborted_reason}`，供 CLI 与
例行任务共用。守卫原样保留：日期不符占比 >1% 中止、覆盖率 <95% 不写、
停牌行跳过、`amt_src='exact'`。

### 2. `sync_today` 改为快照优先

`data_hub/__main__.py` 的 `sync_today` 重构为：

```
today = date.today()                      # run_daily 已确保是交易日
1) 快照补当日：fill_from_snapshot(today)
   - 成功（coverage≥95% 且日期匹配）→ 当日行入库、exact，推进 last_sync_date=today
   - 失败（快照空/日期不符/覆盖率不足）→ 落到步骤 3 的腾讯逐票兜底
2) 补零头：对"快照成功但仍缺当日行"的少量 code（新上市/快照漏），
   走一次 bounded 腾讯逐票（给紧预算，熔断兜底，非致命）
3) 兜底：快照整体失败时，退回现有 sync_kline_db 腾讯逐票全量
   （即当前行为，保证不比现在差）
```

正常交易日的 16:15，走到步骤 1 就结束——秒级、精确、不碰 WAF。
只有在快照异常（如 16:15 前误触发、新浪临时故障）时才退到腾讯逐票。

### 3. `run_daily.sh` 基本不动

仍调 `python -m data_hub sync_today`，该命令内部已变成快照优先。
不改 shell 的触发时序、戳、推送等逻辑。唯一要确认的是：快照优先路径
在 `last_sync_date` 推进上与现有谎报防护一致（不完整轮次不推进）。

## 影响文件

| 文件 | 改动 |
|---|---|
| `scripts/fill_kline_from_snapshot.py` | 抽出 `fill_from_snapshot()`，`main()` 改为调用它 |
| `data_hub/__main__.py` | `sync_today` 改为快照优先 + 零头补拉 + 腾讯兜底 |

**选股策略逻辑不改**：cond1/cond2、25 亿阈值、评分权重不动。
只改"例行任务怎么取当日数据"。

## 边界与异常

- **快照窗口**：16:15 触发时快照持当日定型值，没问题。但 run_daily 有
  "16:15 前不跑"的保护，且快照自带日期守卫（日期≠today 则不写），
  即使误触发也不会把隔日数据写错。
- **非交易日**：run_daily 已在前面做交易日检查，`sync_today` 只在交易日被调用；
  无需在 `sync_today` 内重复判断。
- **last_sync_date**：快照成功且覆盖率达标才推进到 today；覆盖不足或日期不符
  不推进，与现有谎报防护一致。
- **零头补拉**：快照漏的 ~25 只多为停牌/新上市。bounded 腾讯逐票要给紧预算
  （如 300s）+ 熔断，WAF 时快速跳过，不得拖累整轮；补不到也不算失败
  （停牌股本就无当日数据）。
- **成交额精度**：快照 amount 为精确值、标 exact，天然不需要事后 baostock 回标。
  这正是改动的核心收益之一。
- **历史缺口不在本改动范围**：本次只改"当日"例行更新。错过窗口的历史日
  （如本周的 09-30/10-08 尾部）仍需手动/离线补，走各自通路。
- **幂等与并发**：`sync_today` 可能与手动操作并发；upsert 是幂等的，
  `amt_src` 优先级保证 exact 不被覆盖，重复跑安全。

## 预期结果

正常交易日的 16:15 例行任务在**秒级**完成当日数据更新，拿到的是
**精确成交额 + 前不复权快照口径**，且**完全不碰腾讯 WAF**——消除最近两周
"几乎每天手动补"的负担。腾讯逐票退为"快照失败时的兜底"，不再是主力。
手动补数从常态变为异常（仅在新浪也故障、或补历史缺口时才需要）。

## 口径结论（Task 1 已验证）

**快照不复权与前复权在"当日"是同一个值，混用安全。** 实测 10-09 抽样 60 只，
快照 close 与腾讯前复权 close 相对差中位数、P90、max 全为 **0.0000%**，
差异>0.5% 的 0 只。原因：前复权是把历史价调到"今天的基准"，所以今天的前复权价
按定义就等于今天的实际价（快照不复权价）。把当日快照行接到前复权历史序列上，
接点一致，不需要复权换算。唯一的理论接缝只会出现在"历史窗口内发生除权"时，
而那属于历史数据本身的既有口径问题，与本次当日更新无关。因此方案无需加换算。
