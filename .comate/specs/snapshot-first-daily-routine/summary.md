# 完成总结：例行任务改为「收盘后快照优先」

## 改了什么

`run_daily.sh`（launchd 16:15）的当日数据更新，从"腾讯逐票优先"改为
"新浪快照优先"。核心是重写 `data_hub/__main__.py` 的 `sync_today`：

```
1) 快照补当日 fill_from_snapshot(today)
   成功（覆盖率≥95% 且日期匹配）→ 当日行入库(exact) → 推进 last_sync_date
                                → 对少量漏掉的 code 走 bounded 腾讯逐票补零头
   失败（空/日期不符/覆盖率不足）→ 退回腾讯逐票全量兜底（旧行为）
```

正常交易日 16:15 走到第 1 步即结束——秒级、精确成交额、不碰腾讯 WAF。

## 为什么

最近两周（09-14 ~ 10-08）几乎每个交易日的定时同步都因腾讯 WAF 失败或
严重不完整，全靠事后手动补。而新浪快照同期被手动用了十几次，每次 ~2 秒
拿到全市场精确数据、不受 WAF 影响。把它变成例行驱动，手动补从常态变为异常。

## 口径问题已验证（Task 1）

担心"快照不复权 vs 库内腾讯前复权"混用会有价格跳变。实测 10-09 抽样 60 只，
快照 close 与腾讯前复权 close 相对差中位数/P90/max **全为 0.0000%**。
原因：前复权把历史价调到今天基准，所以今天的前复权价按定义等于今天的实际价。
当日快照行接到前复权历史序列上接点一致，**无需复权换算**。

## 测试

- `/tmp/qs_sf_routine.py`：11 项全通过。覆盖 `fill_from_snapshot` 的正常/
  日期不符中止/覆盖率不足中止/停牌跳过；`sync_today` 的快照成功推进+补零头、
  快照失败退回全量兜底、覆盖率不足走兜底且不推进 last_sync_date。

  日期守卫正确判为"快照非当日定型值"→ 退回腾讯 → 腾讯 WAF 早停 →
  last_sync_date 未推进、未写入任何 10-10 脏行。守卫链与兜底链验证通过。
  （happy path 由 mock 测试覆盖，且底层 fill_from_snapshot 本周已多次真实写库成功。）

## 边界与已知点

- **快照窗口**：16:15 触发时快照持当日定型值；run_daily 有"16:15 前不跑"保护，
  且日期守卫兜底，误触发也不会写错日。
- **非交易日**：run_daily 前置交易日检查，sync_today 只在交易日被调用。
- **零头补拉**：快照漏的 ~25 只多为停牌/新上市，bounded 腾讯逐票（300s 预算+熔断），
  WAF 时快速跳过，非致命。
- **历史缺口不在本改动范围**：错过窗口的历史日（如本周 09-30/10-08 尾部的
  1646 只）仍需源恢复后离线补。
- **amt_src**：快照 amount 标 exact，天然不需事后 baostock 回标。
