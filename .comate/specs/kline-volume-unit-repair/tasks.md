# kline 成交量单位修复任务计划

先建巡检工具（Task 1），它同时是修复前后的度量手段——没有度量就无法确认修复是否
真的干净。再修源头（Task 2），最后才动存量数据（Task 3），因为存量修复是不可逆的
写操作，必须在源头已经不再产生坏数据之后做，否则修完又被写脏。

科创板倍率放在最后单独确认（Task 5），它依赖上游恢复，不能阻塞前面的工作。

- [✓] Task 1: 一致性巡检脚本
    - 1.1: 新增 `scripts/audit_kline_integrity.py`，只读、可重复运行
    - 1.2: 按 `amount/(close*volume)` 比值分区间统计行数（<0.5 / 0.5~2 / 2~50 / 50~200 / ≥200）
    - 1.3: 跳过 `close<=0` / `volume<=0` / `amount<=0` 的不可判定行，并单独报告其行数
    - 1.4: 输出受影响的 code 数、日期范围、按年月分布
    - 1.5: 区分「腾讯近似行」（amount == 均价×volume）与其他源，便于归因
    - 1.6: 异常行数为 0 时以退出码 0 结束，非 0 时退出码 1，方便日后接巡检
    - 1.7: 在当前库上跑一次，确认能复现 28,995 行 / 4,233 只票

- [✓] Task 2: 修复 akshare 成交量单位
    - 2.1: `data_hub/sources/akshare.py` 在字段映射后把 `volume` 乘 100
    - 2.2: 注释写明东财 `成交量` 单位是手、统一 schema 要求股，并指向 tencent_kline 的同类换算
    - 2.3: 暂不特殊处理 sh.688/689，留到 Task 5 实测后再定
    - 2.4: 单测：伪造东财风格返回，断言 `volume` 被放大 100 倍且 `amount` 不变
    - 2.5: 单测：修复后 `amount/(close*volume)` 落回 1 附近
    - 2.6: 单测：`成交量` 缺失或为 0 时不报错、不产生负值或 NaN

- [✓] Task 3: 存量坏行修复
    - 3.1: 修复前备份 `stock_data/kline.db`（带时间戳，保留原库）

    - 3.3: `--fix` 默认先打印将影响的行数并要求 `--yes` 确认，避免误触
    - 3.4: 确认幂等：修完再跑 `--fix`，影响行数为 0

    - 3.6: 在备份库上先演练一遍，核对若干已知坏行（如 sh.600110）修复前后的值
    - 3.7: 正式执行，跑巡检确认异常区间归零且未产生新异常区间

- [✓] Task 4: 回归验证
