# 快照优先的补数通路 + 预筛兜底不再空转

## 背景：连续三天的实测对比

| 通路 | 请求数 | 实测耗时 | 结果 |
|---|---|---|---|
| 同步链路（腾讯日K 逐票） 08-31 | 5207 | 34 分钟 | 只落 553 只，失败率 89.4% |
| 同步链路 09-01（launchd） | 300 | 2 小时 15 分 | 0 只，早停中止 |
| 预筛 baostock 兜底 09-01 | 5207×3 | 4 小时 29 分 | 0 行 |
| **新浪快照裸解析** 08-31 | 9 | **1.1 秒** | 5190 行，精确 |
| **新浪快照裸解析** 09-01 | 9 | **1.7 秒** | 5189 行，精确 |

所有日K源都只能逐票请求，只有快照端点是批量的（600 只/请求）。
09-01 的关键证据：18:43 全网取不到，次日 08:10 同一个新浪端点秒出——
那次失败不是"数据不存在"，是取数时机撞上了所有源的窗口期。

## 问题一：快照源丢弃了行情自带的日期

`data_hub/sources/sina.py:36,74`：

```python
today_iso = pd.Timestamp.now().strftime('%Y-%m-%d')   # :36
...
out[bs_code] = {'date': today_iso, ...}               # :74
```

新浪原始响应第 30/31 位就是行情自带的日期与时间（实测
`日期=2026-09-01 时间=15:34:59`），代码从未解析。后果：

- 无法判断拿到的是哪天的行情。次日开盘前调用，会把 09-01 的收盘价
  盖上 09-02 的日期。
- 退市股（国华退、恒久退、赛隆退、天龙退）的末次报价停在 7 月，
  照样会被打上今天的日期。
- 我三次补数都只能绕开这个 API 去裸解析端点——重复实现，且
  `router.py:340` 的 `require_today` 路径同样在用这个错的 date。

## 问题二：预筛兜底会空转 4.5 小时

`daily_select.py:141-160`：

```python
if end_date == today_str:                    # :141 只有当天才走快照
    snapshot = hub.get_market_snapshot(codes)
    ...
    if rows:                                 # :150
        ...
        return ...
    else:
        print("快照返回空，回退 baostock 单只查询")   # :160 一次重试都没有
```

三处缺陷：

1. **快照失败零重试**，直接进 baostock 逐票循环（`:169-202`，
   5207 只 × 最多 3 次重试）。
2. **兜底没有早停**。同步侧已经有 `early_stop_fail_rate` 了，
   预筛这条路没有——前 500 只全失败也会硬跑完剩下 4707 只。
3. **全失败仍写缓存**（`:209` 无条件 `to_csv`），落下一个空文件。
   `cache/` 里那两个 1 字节的 `prefilter_amount_*_final.csv` 就是这么来的。
   下次靠"缓存为空"校验删掉，能自愈，但是噪音。

4. **历史日期取不到快照**。`end_date == today_str` 这个条件把次日
   开盘前这个黄金窗口挡掉了——那时候快照里正好是前一交易日的定型值。

## 技术方案

### 改动一：`sina.py` 解析并返回行情自带日期

```python
# 第 30/31 位是行情自带的日期与时间。之前这里填 pd.Timestamp.now()，
# 导致「拿到的是哪天的行情」无法判断：次日开盘前调用会把前一日收盘
# 盖上今天的日期，退市股的陈旧报价也会被当成当日数据。
quote_date = f[30] if len(f) > 30 else None
if not quote_date:
    continue
out[bs_code] = {
    'date': quote_date,
    'snapshot_time': f[31] if len(f) > 31 else '',
    ...
}
```

`turn` 仍为 0.0（快照不提供换手率），与 `tencent_kline.py` 一致。

**影响面必须逐个确认**：`router.py:340`（`get_kline` 的
`require_today` 分支）与 `daily_select.py:145` 是唯二消费方。
后者只读 `amount`/`name`，不受影响；前者需要读代码确认它拿 `date`
做什么——如果它按 date 建行，这个改动是修正而非破坏，但要有测试兜住。

**已确认（Task 1 实测）**：`router.py:337-345` 把快照行按
`{k: row[k] for k in UNIFIED_COLS}` 直接拼进 df，`date` 原样带入；
守卫只判断 `today_iso not in df['date']`。基线测试暴露两个既有缺陷：

- 快照日期若不是今天，会拼出一行日期为「前一交易日」的重复行
  （实测 `行数=2`，同一日期两条）。
- 配合现状的 `sina.py`（恒填今天），开盘前调用会把前一日收盘
  伪装成今日行——这正是 `require_today` 最不该出错的地方。

第三个消费方：`sina.py:89-95` 的 `SinaSource.get_kline` 同样直接
返回 `date`。它不在 `_kline_source_chain` 里，仅供直接调用，
改动后语义变正确（返回行情真实日期）。

三条既有正确行为必须保住（基线已锁）：快照日期为今天时照常拼接、
`snapshot_time` 不进 `UNIFIED_COLS`、快照为空时安全返回。

### 改动二：新增 `scripts/fill_kline_from_snapshot.py`

把已经手工用了三次的补数流程固化：

```
用法: python3 scripts/fill_kline_from_snapshot.py 2026-09-01
```

- 走 `hub.get_market_snapshot`（改动一之后它能给出真实日期），
  不再裸解析端点。
- 只写 `date == 目标日期` 的行；日期不符的计数并抽样打印。
- 日期不符占比 > 1% 判定为「拿到的不是目标日定型快照」，整体中止。
  少量不符是退市股，跳过即可（实测恒定 4 只）。
- `close/volume/amount` 任一 ≤ 0 视为停牌，跳过。
- 覆盖率 < 95% 不写库。
- `pctChg` 用快照的昨收（第 2 位）算，不依赖库内前一行。

### 改动三：预筛兜底加护栏

```python
# 1) 快照重试：09-01 的证据是全源窗口期故障，重试成本极低（9 个请求）
for attempt in range(SNAPSHOT_RETRIES):
    snapshot = hub.get_market_snapshot(codes)
    if snapshot: break
    time.sleep(SNAPSHOT_BACKOFF_S * (2 ** attempt))

# 2) 放开历史日期：快照自带日期等于目标日就可用
#    （次日开盘前，快照里正是前一交易日的定型值）

# 3) baostock 兜底早停：前 N 只全失败就判定上游不可用
if attempted >= PREFILTER_MIN_SAMPLES and fail_rate > PREFILTER_FAIL_RATE:
    print(f'[预筛] 已尝试 {attempted} 只全部失败，判定上游不可用，中止')
    break

# 4) 空结果不写缓存
if not rows:
    cache_path.unlink(missing_ok=True)
```

## 影响文件

| 文件 | 改动类型 | 说明 |
|---|---|---|
| `data_hub/sources/sina.py` | 修改 | 解析第 30/31 位，`date` 改为行情自带日期 |
| `data_hub/router.py` | 确认/微调 | `:340` require_today 分支对 `date` 的消费方式 |
| `daily_select.py` | 修改 | 快照重试、历史日期放开、兜底早停、空结果不写缓存 |
| `scripts/fill_kline_from_snapshot.py` | 新增 | 按日期批量补 K 线 |

**选股策略逻辑不改**：cond1/cond2 信号条件、25 亿预筛阈值、
评分权重全部不动。这里只改「数据怎么取到」和「取不到时怎么退出」。

## 边界与异常

- 改动一是行为变更，不是纯新增。必须先读 `router.py:340` 再动手，
  并为「快照日期 ≠ 今天」补测试，否则可能悄悄改坏盘中实时判断。
- 补数脚本写的 `turn` 恒为 0，量能类特征若依赖 turn 会受影响——
  但库内既有的腾讯行同样是 0，不是新增退化。
- 快照重试次数要小（建议 3 次、退避 2/4 秒）。这是盘后批处理，
  但 launchd 有 16:15 的时间窗，不能拖成分钟级。
- 兜底早停阈值不能太激进：预筛兜底面对的是全市场，
  前 200 只恰好全是退市股的概率极低，但仍要用「失败率」而非
  「连续失败数」判定，避免误杀。
- 09-01 这类「当天全网取不到、次日才能补」的场景，补出来的选股
  结果时效性已过。脚本只负责把数据补齐，是否重算选股由人决定。

## 预期结果

补数从「34 分钟成 10%」或「2 小时颗粒无收」变成「2 秒拿全市场精确值」。
预筛在上游整体不可用时于分钟级退出，不再空转 4.5 小时，也不再落空缓存。
快照返回的 `date` 可信，次日开盘前补前一交易日成为受支持的正规路径。
